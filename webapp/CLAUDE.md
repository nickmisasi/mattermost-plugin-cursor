# Webapp (React/TypeScript Frontend)

## Stack

- React 18 + TypeScript 4.9 (strict), Webpack 5
- **No Redux for plugin state** and no UI component libraries. Plain function
  components with hooks, plain HTML, one CSS file.
- Tests: Jest 27 + `@testing-library/react` (jsdom).

## Plugin Registration (`index.tsx`)

`initialize(registry, store)` does exactly two things:

1. `registerRightHandSidebarComponent(Panel, 'Cursor Agents')`
2. `registerAppBarComponent(icon, () => store.dispatch(toggleRHSPlugin), 'Cursor Agents', null)`

`store` is only used to dispatch the RHS toggle action; no reducer is
registered. The registry surface the plugin relies on is declared in
`src/types/mattermost-webapp/index.d.ts` -- keep it minimal.

## File Structure

```

  manifest.ts               Generated by `make apply` (gitignored)
  client.ts                 Typed fetch wrapper, ClientError, Client singleton

  hooks/

  utils/

    time.ts                 relativeTime / formatDateTime / formatDuration
    normalize.ts            Defensive API payload -> UI model
    grouping.ts             groupAgentsByRepository (pure, unit tested)
    conversation.ts         Folds a terminal run's result into the messages
    status.ts               Run status -> variant/label
    segments.ts             Splits assistant text on code fences
  testing/fixtures.ts       Shared Agent fixture (imported only by tests)
  components/               Panel (state router) + views
  components/cursor.css     All plugin styling, imported once from index.tsx
```

## State Flow

`Panel` is the only stateful router. It checks `GET /key`, then renders one of:
`SetupView` (connect or manage), `AgentListContainer`, `NewAgentView`, or
`AgentDetailView`. Any request that fails with the `api_key_not_configured`
code calls `onNotConfigured`, which drops the panel back to the setup view.

Data fetching lives in the `hooks/` modules; components stay presentational
where practical so they can be rendered in tests without mocking.

## REST Client (`client.ts`)

Base path `/plugins/<manifest.id>/api/v1`, cookie auth via
`credentials: 'same-origin'`. Non-GET requests send
`X-Requested-With: XMLHttpRequest`. Failures throw `ClientError` carrying
`status` and the server's `code`; `204`/empty bodies resolve to `undefined`.

## Payload Normalization

The plugin passes Cursor API responses through, and that API is in beta, so
**every** raw field is treated as optional. `utils/normalize.ts` converts raw
payloads into the flat `Agent`/`Run`/`ConversationMessage` models; malformed
entries are skipped rather than crashing a render.

Shapes the normalizers are written against:

| Endpoint | Shape |
| --- | --- |
| `GET /agents` | `{items: [...], nextCursor?}` -- `nextCursor` is omitted, never null |
| list item | base `{id, name, status, env: {type}, url, createdAt, updatedAt, latestRunId}` **plus** the plugin's enrichment `{repos: [{url, startingRef?}], branch, prUrl, runStatus}` |
| `GET /agents/{id}` | item fields plus `repos`, `workOnCurrentBranch`, `autoCreatePR` -- **no** execution status |
| `GET /agents/{id}/runs/{runId}` | `{id, agentId, status, createdAt, updatedAt, durationMs?, result?, git?: {branches: [{repoUrl, branch?, prUrl?}]}}` |
| `GET /agents/{id}/messages` | `{id, messages: [{id, type: 'user_message'\|'assistant_message', text}]}` |
| `GET /models` | `{items: [{id, displayName, description?}]}` |
| `GET /repositories` | `{items: [{url}]}` |

Two consequences worth remembering:

- Agent-level `status` is only `ACTIVE`/`ARCHIVED`. Execution status comes from
  the enriched `runStatus` on list items and from the run itself on the detail
  view -- never from `agent.status`.
- Branch, PR URL, `durationMs` and the final `result` live on the **run**. The
  detail view fetches `latestRunId` separately and falls back to it, and
  `utils/conversation.ts` surfaces a terminal run's `result` as the newest
  assistant message when the conversation fetch lags behind.

`includeArchived` defaults to **true** upstream, so `useAgents` always sends it
explicitly. It sends `true` unconditionally and the archived filter is applied
while grouping, which keeps the toggle instant and means no request can be left
in flight for a filter the user has already changed. Every list response is
epoch-checked so a slow reply can never overwrite fresher state, and paging
appends by id so duplicates across pages collapse.

## Streaming

`useRunStream` opens an `EventSource` against
`/agents/{id}/runs/{runId}/stream` while the latest run is `CREATING` or
`RUNNING`, and handles the `status`, `assistant`, `thinking`, `tool_call`,
`result`, `error` and `done` events. jsdom has no `EventSource`, so the hook
guards on `typeof EventSource === 'undefined'` and no-ops in tests.

## Styling Rules

**MUST use Mattermost CSS variables. NEVER hardcode colors.**

- Text: `var(--center-channel-color)`, `rgba(var(--center-channel-color-rgb), 0.56)` for secondary
- Background: `var(--center-channel-bg)`
- Borders: `rgba(var(--center-channel-color-rgb), 0.12)`
- Links: `var(--link-color)`
- Buttons/accent: `var(--button-bg)`, `var(--button-color)`
- Status: `var(--button-bg)` (running), `var(--away-indicator)` (starting),
  `var(--online-indicator)` (finished), `var(--dnd-indicator)` (failed)

**Use native Mattermost button classes** -- `btn btn-primary`, `btn btn-danger`,
`btn btn-tertiary`, `btn btn-link` -- and Mattermost's compass icon font
(`icon icon-pencil-outline`, `icon icon-magnify`, `icon icon-source-branch`,
`icon icon-source-pull`, ...). Spacing follows the 4px grid.

## Build Commands

```bash
cd webapp
npm run build                 # Production build
npm run debug                 # Development build (no minification)
npm test -- --watchAll=false  # Tests
npm run lint                  # ESLint (npm run fix to autofix import order)
npm run check-types           # TypeScript
```

## Webpack Externals

React, ReactDOM, Redux, ReactRedux, PropTypes, ReactBootstrap and
ReactRouterDom are **provided by the Mattermost host app** and must not be
bundled. `react-dom` and `@testing-library/react` are devDependencies used only
by Jest.

## Common Pitfalls

- **No hardcoded colors**: every color comes from a CSS variable so both themes work.
- **No custom button styles**: use `btn btn-primary` etc.
- **`manifest.ts` is generated**: run `make apply` from the repo root. It is
  gitignored, so a fresh checkout has to generate it before building.
- **ESLint `no-void`**: the shared config bans the `void` operator, so async
  calls are made as plain statements rather than `void promise`.
- **Keep files small**: split components rather than growing a file past ~400 lines.
